# M2 retrieval labeling

The full embedding run requires approval after the measured CPU benchmark. Labeling
begins only when all corpus documents are parsed and all chunks have compatible
embeddings. The CLI checks these conditions and freezes the corpus before accepting
questions; it will refuse a partially embedded corpus.

Use the project Python from PowerShell:

```powershell
.venv/Scripts/python.exe -m evals.label_retrieval --corpus CORPUS_ID
```

Replace `CORPUS_ID` with the finalized ID in `docs/M2_STATUS.md`. Alternatively set
`RETRIEVAL_CORPUS` in your local `.env`. No API key is needed.

Enter your question. The tool retrieves 30 candidates per mode (vector, keyword,
hybrid, hybrid_rerank) and combines them by chunk ID. No candidates are selected
automatically. The initial search can take time while the CPU reranker loads.

Commands:

| Command | Effect |
|---|---|
| `list` | Show numbered candidates with IDs and filing metadata; `*` marks your selections |
| `pool` | Page through every combined candidate with full text and provenance |
| `show 3` or `show CHUNK_ID` | Page through full passage text, source metadata, and mode ranks |
| `mark 3` / `unmark 3` | Add/remove your relevance label; chunk IDs also work |
| `more 60` | Increase candidate depth across all four modes |
| `filters {"ticker":"MSFT","fiscal_year":2025,"fiscal_period":"Q3"}` | Rerun with explicit filing-period filters |
| `browse ACCESSION` | Add all chunks from a filing to the candidate list |
| `browse ACCESSION P1-2` | Add chunks from one section |
| `reference` | Enter your optional reference answer |
| `save` | Save this question and your selected gold chunks to `evals/handwritten.jsonl` |
| `quit` | Preserve the current draft and exit |

Questions must fit the reranker's 48-token query budget. The 48-token budget is
measured with the reranker tokenizer; ordinary passage/query pairs are checked
against 512 at construction and scoring time. Oversized indivisible table rows
are explicitly flagged and scored in windows while retaining one citation ID.

Each finalized question needs at least one gold chunk. If none of the candidates
are correct, increase depth or browse the source filing rather than selecting an
incorrect passage. All selected chunks must come from the frozen corpus.

Drafts are saved to ignored `evals/handwritten.draft.json`; rerunning resumes the
draft. To edit a saved record, enter `:edit QUESTION_ID` at the question prompt.
Enter `:quit` at that prompt to exit. Candidate numbers may change after another
search; the saved labels always use stable chunk IDs.

Write and label at least 30 questions yourself. No questions, reference answers,
or gold labels are generated by the implementation. Pooled candidates are a
labeling aid and are not exhaustive relevance ground truth.

After you tell the coding agent that labeling is finished, it will run:

```powershell
.venv/Scripts/python.exe -m evals.retrieval_eval
```

The evaluator validates question count, chunk membership and the frozen corpus
fingerprint before writing `evals/results/retrieval.md`. It reports macro recall@5,
recall@10 and MRR@30 for all four modes. M3 remains gated on your M2 acceptance.
